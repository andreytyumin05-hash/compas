# compas — Telegram → AI → КОМПАС-3D

Проект превращает текстовое описание детали или фото чертежа в редактируемую 3D-модель КОМПАС-3D. Основной пользовательский интерфейс — Telegram-бот. На Windows бот работает на том же ПК, где запущен КОМПАС-3D; Python-ядро управляет КОМПАС через COM API5/API7.

## Рабочий контур

```text
Telegram
  │
  ├─ текстовое ТЗ
  │       │
  └─ фото чертежа
          ▼
      agent / vision
          │
          ▼
   CAD contract + validation
          │
          ▼
       agent.build
          │
          ▼
      core (COM KOMPAS)
          │
          ▼
      KOMPAS-3D
          │
          ▼
 .compas_tmp/latest_model.m3d
```

В репозитории также находится KOMPAS AddIn `AI CAD`. Это интеграционный интерфейс внутри KOMPAS, который использует тот же Python-agent и `core`; отдельного CAD-ядра в AddIn нет.

## Структура

```text
compas/
├── agent/        LLM, vision, контракт, промпты, validation, build, repair
├── bot/          Telegram-бот и очередь задач
├── core/         COM-обёртка КОМПАС, эскизы, операции, параметры, экспорт
├── addon/        интеграция AI CAD в KOMPAS
├── knowledge/    CAD-паттерны и инженерные правила
├── tests/        регрессионные тесты агентного конвейера
├── requirements.txt
├── .env.example
└── README.md
```

## Telegram

В `.env` задаются:

```text
TELEGRAM_BOT_TOKEN=...
LLM_PROVIDER=groq|gemini|openrouter
GROQ_API_KEY=...
GEMINI_API_KEY=...
OPENROUTER_API_KEY=...
LLM_MODEL=...
```

Запуск:

```powershell
python -m bot
```

Перед запуском должен быть открыт КОМПАС-3D.

Бот принимает:

- текстовое инженерное ТЗ;
- фотографию/скан чертежа;
- подтверждение распознанного vision-контракта.

После построения бот отправляет только `latest_model.m3d`. Старые пользовательские файлы из временной рабочей области удаляются; сохраняется один последний контекст для следующего изменения модели.

## AddIn KOMPAS

`addon/` содержит COM/ActiveX AddIn для KOMPAS-3D v23 x64.

Установка на Windows:

```powershell
.\addon\install.ps1
```

Установщик:

1. собирает `CompasAiCad.csproj` под .NET Framework 4.8 x64;
2. регистрирует COM-класс через `RegAsm`;
3. регистрирует KOMPAS AddIn через `HKCU\Software\ASCON\KOMPAS-3D\AddIns\CompasAiCad`;
4. сохраняет пути репозитория и Python для runtime.

Все CAD-операции остаются в Python `core`; AddIn только предоставляет интерфейс и вызывает `addon.bridge`.

## Core

Главная точка API для агента:

```python
from core import Part

part = Part.create("Деталь")

with part.sketch("xy") as sk:
    sk.circle(0, 0, 20)

part.extrude(sk, depth=50)
part.update()
```

Поддерживаемые направления включают эскизы, окружности/линии/прямоугольники/пазы, выдавливание, вырезы, вращения, фаски, скругления, отверстия, параметры и связи, а также spline/Bezier-профили.

Для валов и тел вращения агент должен предпочитать `revolve`, а для отверстий, заданных как сквозные, использовать явную семантику `through_all=True`.

## Параметры

`Part.param()` / `Part.p()` задают именованные параметры и зависимости. Python-граф параметров является частью runtime; привязка к нативным переменным/размерам КОМПАС выполняется в `core/params.py`.

Целевой сценарий:

```text
W = 100
hole_x = W / 2
```

После изменения `W` модель должна перестраиваться с новым положением отверстия.

## Vision

Vision превращает фото чертежа в канонический CAD-контракт. Бот показывает пользователю распознанные размеры/элементы и только после подтверждения передаёт контракт агенту построения.

Для сложных деталей контракт должен содержать как минимум габариты, ступени, отверстия, PCD, пазы/канавки, фаски/скругления и типы профилей, когда они различимы по чертежу.

## Validation и tests

Сгенерированный код проходит статическую проверку до исполнения. Запрещены прямые `win32com`/произвольные импорты в LLM-коде; агент работает через публичный `core` API.

Регрессионные тесты находятся в `tests/` и предназначены для проверки контрактов, шаблонов, validator/critic, offline-пайплайна и vision fallback.

Запуск:

```powershell
python -m unittest discover -s tests -p "test_*.py"
```

## Важное

`main` — стабильная ветка. Вся активная разработка ведётся в `features/vision`.

Не коммитьте `.env`, `venv`, `.compas_tmp`, результаты сборки C# и файлы моделей КОМПАС.
